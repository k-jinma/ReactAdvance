# 課題3：追加と削除をデータベースに保存する

課題2では、一覧の取得だけをデータベースにつなぎました。今度は、タスクの追加と削除も、データベースに保存するようにします。

## ステップI：tasksApi.ts に createTask と deleteTask を足す

```ts
// src/lib/tasksApi.ts(課題3)
import { supabase } from "./supabase";
import type { Task, TaskStatus } from "../types/task"; // ← 変更:TaskStatus も読み込む

// タスクの一覧を取ってくる関数
// SQL の select id, title, status from review_tasks order by id; と同じ
export async function fetchTasks(): Promise<Task[]> {
  const { data, error } = await supabase
    .from("review_tasks")
    .select("id, title, status")
    .order("id");

  if (error) throw error; // 失敗したらエラーを投げる

  // DB の id は数値なので、アプリの Task に合わせて文字列に変える
  return data.map((row) => ({
    id: String(row.id),
    title: row.title,
    status: row.status,
  }));
}

// ← 追加:タスクを1件追加する関数
// SQL の insert into review_tasks (title, status) values ('タイトル', 'todo'); と同じ
export async function createTask(newTask: { title: string; status: TaskStatus }): Promise<void> {
  const { error } = await supabase.from("review_tasks").insert(newTask);
  if (error) throw error;
}

// ← 追加:タスクを1件削除する関数
// SQL の delete from review_tasks where id = 番号; と同じ
export async function deleteTask(id: string): Promise<void> {
  const { error } = await supabase.from("review_tasks").delete().eq("id", id);
  if (error) throw error;
}
```

<b>createTask</b> は、<code>.insert(newTask)</code> で1件を追加します。<code>{ title: "デプロイ", status: "doing" }</code> のようなオブジェクトを渡すと、キーの名前と同じ名前の列に値が入ります。id と created\_at は渡していないので、課題1と同じように、データベースが自動で入れます。

<b>deleteTask</b> は、<code>.delete().eq("id", id)</code> で1件を削除します。<code>.eq("id", id)</code> は「id 列の値が、引数で受け取った id と等しい行」という指定で、SQL の <code>where id = 番号</code> にあたります。

どちらの関数も、成功したときに返す値はないので、戻り値の型は <code>Promise<void></code> です。失敗したときは、fetchTasks と同じく throw します。

## ステップJ：handleAdd と handleDelete を書き換える

```ts
// src/App.tsx(課題3)
import { useState, useEffect } from "react";
import type { Task, TaskStatus } from "./types/task";
import { Column } from "./components/Column";
import { fetchTasks, createTask, deleteTask } from "./lib/tasksApi"; // ← 変更:createTask と deleteTask も読み込む

function App() {
  const [tasks, setTasks] = useState<Task[]>([]);
  const [title, setTitle] = useState("");
  const [status, setStatus] = useState<TaskStatus>("todo");
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetchTasks().then((data) => {
      setTasks(data);
      setLoading(false);
    });
  }, []);

  // ← 変更:DB に追加してから、一覧を取り直す
  const handleAdd = async () => {
    if (!title) return;
    await createTask({ title, status }); // DB に1件追加する
    const data = await fetchTasks(); // 一覧を取り直す
    setTasks(data);
    setTitle("");
  };

  // ← 変更:DB から削除してから、一覧を取り直す
  const handleDelete = async (id: string) => {
    await deleteTask(id); // DB から1件削除する
    const data = await fetchTasks(); // 一覧を取り直す
    setTasks(data);
  };

  if (loading) return <p style={{ padding: 24 }}>読み込み中...</p>;

  return (
    <div style={{ padding: 24, fontFamily: "sans-serif" }}>
      <h1>mini-board</h1>
      <input value={title} onChange={(e) => setTitle(e.target.value)} placeholder="新しいタスク" />
      <select value={status} onChange={(e) => setStatus(e.target.value as TaskStatus)}>
        <option value="todo">ToDo</option>
        <option value="doing">Doing</option>
        <option value="done">Done</option>
      </select>
      <button onClick={handleAdd}>+ 追加</button>

      <div style={{ display: "flex", gap: 16, marginTop: 16 }}>
        <Column status="todo" title="ToDo" tasks={tasks} onDelete={handleDelete} />
        <Column status="doing" title="Doing" tasks={tasks} onDelete={handleDelete} />
        <Column status="done" title="Done" tasks={tasks} onDelete={handleDelete} />
      </div>
    </div>
  );
}

export default App;
```

handleAdd と handleDelete に <code>async</code> を付けて、中で <code>await</code> を使えるようにしています。追加・削除がデータベースで終わるのを待ってから、<b>fetchTasks で一覧を取り直し</b>、setTasks で画面に反映しています。

一覧を取り直すのは、画面の tasks が「前に取ってきたときの一覧」だからです。データベースの中身を変えても、画面の tasks は自動では変わりません。そこで、データベースを変えたら、もう一度一覧を取ってきて、画面とデータベースをそろえます。追加したタスクの id はデータベースが決めるので、取り直せば、正しい id の付いたタスクが画面に入ります。

## 動作確認

1. タスク名を入力し、レーンを選んで「+ 追加」を押すと、そのレーンにタスクが増える
2. 画面を再読み込みしても、追加したタスクが残っている
3. Supabase の Table Editor で review\_tasks を開くと、追加した行が増えている
4. 削除ボタンを押すと消え、再読み込みしても戻ってこない

# 課題4：TanStack Query に置き換える

課題3の App.tsx は、データベースとやりとりできるようになりました。ただし、tasks と loading の state、useEffect、追加・削除のあとの取り直しを、すべて自分で書いています。失敗したときの表示もありません。

<b>TanStack Query</b> は、「データを取ってくる」「取ってきたデータを覚えておく」「古くなったら取り直す」をまとめて引き受けてくれるライブラリです。課題3と同じ動きのまま、App.tsx を短くしていきます。

## ステップK：インストールと QueryClientProvider

```bash
# ターミナル(mini-board のフォルダで実行)
npm install @tanstack/react-query
```

次に、<code>src/main.tsx</code> を書き換えます。

```ts
// src/main.tsx(課題4 ステップK)
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    {/* ← 追加:App 全体を QueryClientProvider で囲む */}

  </StrictMode>,

```

<code>QueryClient</code> は、取ってきたデータを覚えておく入れ物です。この入れ物を <code>QueryClientProvider</code> で App 全体に渡しておくと、App の中で useQuery や useMutation が使えるようになります。

## ステップL：useQuery で一覧を取ってくる

```ts
// src/App.tsx(課題4 ステップL)
import { useState } from "react"; // ← 変更:useEffect は使わなくなる
import { useQuery, useQueryClient } from "@tanstack/react-query"; // ← 追加
import type { TaskStatus } from "./types/task"; // ← 変更:Task は使わなくなる
import { Column } from "./components/Column";
import { fetchTasks, createTask, deleteTask } from "./lib/tasksApi";

function App() {
  const [title, setTitle] = useState("");
  const [status, setStatus] = useState<TaskStatus>("todo");

  // ← 追加:tasks・loading の state と useEffect の代わりに、useQuery で一覧を取ってくる
  const { data: tasks = [], isPending, isError, error } = useQuery({
    queryKey: ["tasks"],
    queryFn: fetchTasks,
  });
  const queryClient = useQueryClient(); // ← 追加

  const handleAdd = async () => {
    if (!title) return;
    await createTask({ title, status });
    queryClient.invalidateQueries({ queryKey: ["tasks"] }); // ← 変更:一覧を取り直してもらう
    setTitle("");
  };

  const handleDelete = async (id: string) => {
    await deleteTask(id);
    queryClient.invalidateQueries({ queryKey: ["tasks"] }); // ← 変更:一覧を取り直してもらう
  };

  if (isPending) return <p style={{ padding: 24 }}>読み込み中...</p>; // ← 変更:loading → isPending
  // ← 追加:失敗したときは、エラーの文章を表示する
  if (isError) return <p style={{ padding: 24, color: "crimson" }}>エラー:{error.message}</p>;

  return (
    <div style={{ padding: 24, fontFamily: "sans-serif" }}>
      <h1>mini-board</h1>
      <input value={title} onChange={(e) => setTitle(e.target.value)} placeholder="新しいタスク" />
      <select value={status} onChange={(e) => setStatus(e.target.value as TaskStatus)}>
        <option value="todo">ToDo</option>
        <option value="doing">Doing</option>
        <option value="done">Done</option>
      </select>
      <button onClick={handleAdd}>+ 追加</button>

      <div style={{ display: "flex", gap: 16, marginTop: 16 }}>
        <Column status="todo" title="ToDo" tasks={tasks} onDelete={handleDelete} />
        <Column status="doing" title="Doing" tasks={tasks} onDelete={handleDelete} />
        <Column status="done" title="Done" tasks={tasks} onDelete={handleDelete} />
      </div>
    </div>
  );
}

export default App;
```

tasks と loading の state、そして useEffect が、<b>useQuery</b> の呼び出し1つに置き換わりました。useQuery には、2つのことを渡します。

1. <b>queryKey</b> ― 取ってきたデータに付ける名札です。ここでは <code>["tasks"]</code> にしています
2. <b>queryFn</b> ― データの取り方です。課題2で作った fetchTasks を、そのまま渡しています

useQuery は、画面に登場したときに queryFn を呼び、結果を QueryClient に覚えておきます。戻り値からは、次の値を取り出しています。

- <code>data</code> ― 取ってきたデータです。<code>data: tasks = []</code> は、「data を tasks という名前で受け取り、まだデータがないときは空の配列にする」という書き方です(分割代入の別名とデフォルト値)
- <code>isPending</code> ― まだデータが届いていない間は true です。第3回の loading の代わりになります
- <code>isError</code> と <code>error</code> ― 失敗したら isError が true になり、error にエラーの内容が入ります。fetchTasks が throw したエラーを、useQuery が受け止めてくれます

追加と削除のあとは、<code>queryClient.invalidateQueries({ queryKey: ["tasks"] })</code> を呼んでいます。これは、「tasks という名札のデータは古くなった」と QueryClient に伝える命令です。伝えると、useQuery が自動で fetchTasks を呼び直し、画面が最新の一覧に変わります。課題3で書いた「一覧を取り直して setTasks する」2行を、この1行が代わりに行います。

import も変わっています。useEffect と Task は使わなくなったので、読み込みから外します。第3回のステップCと同じで、使っていない import を残すと TypeScript のエラーになります。

## ステップM：useMutation で追加・削除を包む

最後に、追加と削除の処理を <b>useMutation</b> で包みます。useQuery が「取ってくる」ためのフックなのに対して、useMutation は「データベースを変える」ためのフックです。

```ts
// src/App.tsx(課題4 ステップM)
import { useState } from "react";
import { useQuery, useMutation, useQueryClient } from "@tanstack/react-query"; // ← 変更:useMutation も読み込む
import type { TaskStatus } from "./types/task";
import { Column } from "./components/Column";
import { fetchTasks, createTask, deleteTask } from "./lib/tasksApi";

function App() {
  const [title, setTitle] = useState("");
  const [status, setStatus] = useState<TaskStatus>("todo");

  const { data: tasks = [], isPending, isError, error } = useQuery({
    queryKey: ["tasks"],
    queryFn: fetchTasks,
  });
  const queryClient = useQueryClient();

  // ← 追加:追加の処理を useMutation で包む
  const addMutation = useMutation({
    mutationFn: createTask,
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ["tasks"] }),
  });

  // ← 追加:削除の処理を useMutation で包む
  const deleteMutation = useMutation({
    mutationFn: deleteTask,
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ["tasks"] }),
  });

  // ← 変更:mutate を呼ぶだけになる(async も不要)
  const handleAdd = () => {
    if (!title) return;
    addMutation.mutate({ title, status });
    setTitle("");
  };

  // ← 変更:mutate を呼ぶだけになる
  const handleDelete = (id: string) => {
    deleteMutation.mutate(id);
  };

  if (isPending) return <p style={{ padding: 24 }}>読み込み中...</p>;
  if (isError) return <p style={{ padding: 24, color: "crimson" }}>エラー:{error.message}</p>;

  return (
    <div style={{ padding: 24, fontFamily: "sans-serif" }}>
      <h1>mini-board</h1>
      <input value={title} onChange={(e) => setTitle(e.target.value)} placeholder="新しいタスク" />
      <select value={status} onChange={(e) => setStatus(e.target.value as TaskStatus)}>
        <option value="todo">ToDo</option>
        <option value="doing">Doing</option>
        <option value="done">Done</option>
      </select>
      {/* ← 変更:追加している間はボタンを押せなくする */}
      <button onClick={handleAdd} disabled={addMutation.isPending}>
        {addMutation.isPending ? "追加中..." : "+ 追加"}
      </button>

      <div style={{ display: "flex", gap: 16, marginTop: 16 }}>
        <Column status="todo" title="ToDo" tasks={tasks} onDelete={handleDelete} />
        <Column status="doing" title="Doing" tasks={tasks} onDelete={handleDelete} />
        <Column status="done" title="Done" tasks={tasks} onDelete={handleDelete} />
      </div>
    </div>
  );
}

export default App;
```

useMutation には、2つのことを渡します。

1. <b>mutationFn</b> ― 実行する関数です。tasksApi.ts の createTask と deleteTask を、そのまま渡しています
2. <b>onSuccess</b> ― 成功したあとにすることです。ステップLで handleAdd に書いていた invalidateQueries を、ここに移しています

handleAdd と handleDelete は、<code>addMutation.mutate({ title, status })</code> のように mutate を呼ぶだけになりました。mutate に渡した値が、mutationFn(createTask)の引数になります。await もいらないので、async も外しています。

useMutation の戻り値には、<code>isPending</code>(実行中かどうか)も入っています。追加している間は、ボタンを押せなくして「追加中...」と表示するようにしました。何度も押されて、同じタスクが2件追加されるのを防げます。

## 動作確認

1. 画面を開くと「読み込み中...」のあとで、データベースのタスクが表示される
2. タスクを追加すると、ボタンが一瞬「追加中...」になり、そのあと選んだレーンに増える

<callout icon="💡" color="gray_bg">
第3回と第4回で、同じことをどう書いたかを並べてみます。

- tasks の state → useQuery の <code>data</code>
- loading の state → <code>isPending</code>
- useEffect と依存配列 <code>[]</code> → useQuery が、画面に登場したときに自動で取ってくる
- 失敗したときの state と try/catch → <code>isError</code> と <code>error</code>
- 追加・削除のあとの取り直し → useMutation の onSuccess で <code>invalidateQueries</code>

TanStack Query の中では、第3回で自分で書いた useState や useEffect と同じことが行われています。仕組みを知ったうえで使うと、何が起きているのかを想像しながらコードを読めます。
</callout>

# 🏆 追加チャレンジ

課題1で練習した <b>UPDATE</b> を、アプリから使ってみます。各タスクカードにステータスを選ぶセレクトを付け、選び直すと、そのタスクが別のレーンに移るようにしてください。データベースにも保存して、再読み込みしても移ったままになるようにします。

1. tasksApi.ts に、ステータスを書き換える関数 <code>updateTaskStatus</code> を足す(SQL の <code>update review_tasks set status = ... where id = ...;</code> にあたる処理を、<code>.update()</code> と <code>.eq()</code> で書く)
2. App.tsx で、updateTaskStatus を useMutation で包み、成功したら invalidateQueries で一覧を取り直す
3. 第2回の onDelete と同じように、App → Column → TaskCard の順に、ステータスを変える関数を props で渡す。TaskCard にはセレクトを置き、選ばれたらその関数を呼ぶ

次回(第5回)は、useContext・useForm・useDraggable/useDroppable など、ほかのフックの使い方を棚卸しします。

まず、tasksApi.ts の最後に updateTaskStatus を足します。

```ts
// src/lib/tasksApi.ts(追加チャレンジ)
import { supabase } from "./supabase";
import type { Task, TaskStatus } from "../types/task";

// タスクの一覧を取ってくる関数
// SQL の select id, title, status from review_tasks order by id; と同じ
export async function fetchTasks(): Promise<Task[]> {
  const { data, error } = await supabase
    .from("review_tasks")
    .select("id, title, status")
    .order("id");

  if (error) throw error; // 失敗したらエラーを投げる

  // DB の id は数値なので、アプリの Task に合わせて文字列に変える
  return data.map((row) => ({
    id: String(row.id),
    title: row.title,
    status: row.status,
  }));
}

// タスクを1件追加する関数
// SQL の insert into review_tasks (title, status) values ('タイトル', 'todo'); と同じ
export async function createTask(newTask: { title: string; status: TaskStatus }): Promise<void> {
  const { error } = await supabase.from("review_tasks").insert(newTask);
  if (error) throw error;
}

// タスクを1件削除する関数
// SQL の delete from review_tasks where id = 番号; と同じ
export async function deleteTask(id: string): Promise<void> {
  const { error } = await supabase.from("review_tasks").delete().eq("id", id);
  if (error) throw error;
}

// ← 追加:タスクのステータスを変える関数
// SQL の update review_tasks set status = 'doing' where id = 番号; と同じ
export async function updateTaskStatus(target: { id: string; status: TaskStatus }): Promise<void> {
  const { error } = await supabase
    .from("review_tasks")
    .update({ status: target.status })
    .eq("id", target.id);
  if (error) throw error;
}
```

<code>.update({ status: target.status })</code> が SQL の <code>set status = ...</code>、<code>.eq("id", target.id)</code> が <code>where id = ...</code> にあたります。useMutation の mutationFn は引数を1つしか受け取らないので、id と status を1つのオブジェクトにまとめて受け取っています。createTask で <code>{ title, status }</code> を受け取ったのと同じ形です。

```ts
// src/components/TaskCard.tsx(追加チャレンジ)
import type { Task, TaskStatus } from "../types/task"; // ← 変更:TaskStatus も読み込む

type Props = {
  task: Task;
  onDelete: (id: string) => void;
  onChangeStatus: (id: string, status: TaskStatus) => void; // ← 追加
};

export function TaskCard({ task, onDelete, onChangeStatus }: Props) {
  return (
    <div className="task-card" style={{ display: "flex", justifyContent: "space-between" }}>
      {task.title}
      <div>
        {/* ← 追加:ステータスを選ぶセレクト */}
        <select
          value={task.status}
          onChange={(e) => onChangeStatus(task.id, e.target.value as TaskStatus)}
        >
          <option value="todo">ToDo</option>
          <option value="doing">Doing</option>
          <option value="done">Done</option>
        </select>
        <button onClick={() => onDelete(task.id)}>削除</button>
      </div>
    </div>

```

セレクトの value には、そのタスクの今の status を入れています。別の値が選ばれたら、<code>onChangeStatus(task.id, 選ばれた値)</code> を呼びます。

```ts
// src/components/Column.tsx(追加チャレンジ)
import type { Task, TaskStatus } from "../types/task";
import { TaskCard } from "./TaskCard";

type Props = {
  status: TaskStatus;
  title: string;
  tasks: Task[];
  onDelete: (id: string) => void;
  onChangeStatus: (id: string, status: TaskStatus) => void; // ← 追加

  const items = tasks.filter((task) => task.status === status);

  return (
    <div className="column">
      <h2>
        {title}({items.length})
      </h2>

    </div>
  );
}
```

最後に App.tsx で、updateTaskStatus を useMutation で包み、3つの Column に渡します。

```ts
// src/App.tsx(追加チャレンジ)
import { useState } from "react";
import { useQuery, useMutation, useQueryClient } from "@tanstack/react-query";
import type { TaskStatus } from "./types/task";
import { Column } from "./components/Column";
import { fetchTasks, createTask, deleteTask, updateTaskStatus } from "./lib/tasksApi"; // ← 変更:updateTaskStatus も読み込む

function App() {
  const [title, setTitle] = useState("");
  const [status, setStatus] = useState<TaskStatus>("todo");

  const { data: tasks = [], isPending, isError, error } = useQuery({
    queryKey: ["tasks"],
    queryFn: fetchTasks,
  });
  const queryClient = useQueryClient();

  const addMutation = useMutation({
    mutationFn: createTask,
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ["tasks"] }),
  });

  const deleteMutation = useMutation({
    mutationFn: deleteTask,
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ["tasks"] }),
  });

  // ← 追加:ステータス変更の処理を useMutation で包む
  const updateMutation = useMutation({
    mutationFn: updateTaskStatus,
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ["tasks"] }),
  });

  const handleAdd = () => {
    if (!title) return;
    addMutation.mutate({ title, status });
    setTitle("");
  };

  const handleDelete = (id: string) => {
    deleteMutation.mutate(id);
  };

  // ← 追加:セレクトでステータスが選ばれたら、DB を書き換える
  const handleChangeStatus = (id: string, newStatus: TaskStatus) => {
    updateMutation.mutate({ id, status: newStatus });
  };

  if (isPending) return <p style={{ padding: 24 }}>読み込み中...</p>;
  if (isError) return <p style={{ padding: 24, color: "crimson" }}>エラー:{error.message}</p>;

  return (
    <div style={{ padding: 24, fontFamily: "sans-serif" }}>
      <h1>mini-board</h1>
      <input value={title} onChange={(e) => setTitle(e.target.value)} placeholder="新しいタスク" />
      <select value={status} onChange={(e) => setStatus(e.target.value as TaskStatus)}>
        <option value="todo">ToDo</option>
        <option value="doing">Doing</option>
        <option value="done">Done</option>
      </select>
      <button onClick={handleAdd} disabled={addMutation.isPending}>
        {addMutation.isPending ? "追加中..." : "+ 追加"}
      </button>

      {/* ← 変更:3つの Column に onChangeStatus を渡す */}
      <div style={{ display: "flex", gap: 16, marginTop: 16 }}>
        <Column status="todo" title="ToDo" tasks={tasks} onDelete={handleDelete} onChangeStatus={handleChangeStatus} />
        <Column status="doing" title="Doing" tasks={tasks} onDelete={handleDelete} onChangeStatus={handleChangeStatus} />
        <Column status="done" title="Done" tasks={tasks} onDelete={handleDelete} onChangeStatus={handleChangeStatus} />
      </div>
    </div>
  );
}

export default App;
```

App.tsx には、入力欄の横のセレクト用に status という state がすでにあります。handleChangeStatus の引数は、それと区別するために newStatus という名前にしています。

セレクトで「テスト」を Doing に変えると、Doing のレーンに移ります。再読み込みしても Doing のままで、SQL Editor で select を実行すると、status が doing に変わっていることも確かめられます。
